# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**Konsilys** (konsilys.fr) — a SaaS platform for ESNs (IT consulting firms): staffing, missions & margin, planning, absences with N+1 approval, recruitment and CRM. Multi-tenant, one isolated space per company.

## Stack & how it runs

- **Frontend:** plain HTML/CSS/**vanilla JavaScript — no framework, no build step, no npm, no bundler.** The Supabase JS client is loaded from a CDN `<script>`. To run locally, just open the HTML files in a browser (or `file://`).
- **Backend:** Supabase — PostgreSQL + auto-generated REST API + Auth (JWT) + Row Level Security. **Prod project id: `rwmstlesxnglpblrurqj`** (livemode).
- **Server-side logic:** Supabase **Edge Functions** in **TypeScript / Deno** (`supabase/functions/`).
- **Payments:** Stripe (livemode). **Hosting:** Vercel (front) + Supabase (data, in Europe).

**Two domains, one Vercel project.** `konsilys.fr` = the SaaS (everything below). **`konsilys.com` = Konsilys's « création de sites internet à Lyon » offer** (artisans & shops; static pages in `com/`, own stylesheet `com/com.css`). **The offer pages are generated** by `node scripts/build-com.cjs` (hub `com/index.html` + one page per trade `com/<metier>.html` + `sitemap-com.xml`): edit the script, re-run it, commit the outputs (no build on Vercel). On host `(www.)konsilys.com`, `/` redirects (307) to `/creation-site-internet` (hub), `/creation-site-internet/<metier>` serves the trade pages (batiment, restaurant, coiffeur, fleuriste, boulangerie); host-conditioned rewrites serve `/mentions-legales`, `/apercu/<token>` (private prospect mock-up: `com/apercu.html` fetches the HTML from the `apercu` Edge Function of the separate Supabase project `hxxbhbfueqwsvwqrojea`, repo `facade` — no prospect data in this repo) and `/desinscription?t=` (prospecting unsubscribe, `unsubscribe` function of the same project), and `/studio` (`com/studio.html`: Charles's private mobile tool for street prospecting — search a shop in the official company register, fill its details, the mock-up is saved and online at once on `/apercu/<token>`, with live preview, QR code and share button; calls the `studio` Edge Function of the same project, protected by an access code kept on his phone). Those paths are noindex and 404 on konsilys.fr. SaaS routes (`/app`, `/login`…) keep working on both domains.

Routes (`vercel.json`): `/`→`index.html` (marketing home), `/fonctionnalites`, `/solutions`, `/tarifs` (pricing + subscription configurator), `/essai-gratuit` (14-day free-trial signup), `/demo` (demo request → `leads` table), `/login`→`esn_login.html`, `/app`→`esn_manager_cgi.html` (the product), `/cgu`→`cgu.html`.

## Build / test / lint

No build step, no linter, no CI. There **is** a lightweight E2E suite:
- **E2E (Playwright, no npm)** — `node tests/e2e.cjs` loads the pages in `file://` with a stubbed Supabase CDN (runs offline) and checks landing/login/app-demo boot, navigation on every tab, and key features (forecast, BU/Practice margin). Non-zero exit on regression. Run it after any change to the front. See `tests/README.md`.
- **JS syntax check** — validate the `js/*.js` modules: `for f in js/*.js; do node --check "$f"; done` (or, for inline `<script>` blocks in `index.html`/`esn_login.html`):
  `node -e 'const fs=require("fs"),vm=require("vm");const h=fs.readFileSync("index.html","utf8");let m,re=/<script\b[^>]*>([\s\S]*?)<\/script>/gi;while((m=re.exec(h)))try{new vm.Script(m[1])}catch(e){console.log(e.message)}'`
- **Visual/behaviour check** — render with headless Chromium via Playwright (`/opt/node22/bin/node`, chromium at `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`). Take screenshots at 390px to check mobile. **LibreOffice/soffice is broken in this env** — don't use it; for PDFs, render HTML with Chromium `page.pdf()`.

## Frontend architecture (the important part)

`esn_manager_cgi.html` is the product app (a hand-rolled SPA). Its JavaScript is **split into ordered classic scripts under `js/`** (loaded via `<script src>` after the Supabase CDN, no build step). They share one global scope — **order matters**, and everything is `var`/`function` (no top-level `const`/`let`, which would not cross files). Modules by concern:
  `01-core` (Supabase client, date/fiscal utils, KPI engine, global state `S`, constants) · `02-recommendations` · `03-sidebar` (nav) · `04-dashboard` · `05-missions-planning` · `06-kpis` (KPIs + forecast/BU-Practice) · `07-leaves` · `08-access-admin` (Gestion des accès + audit log view) · `09-business` (CRM) · `10-help-tutorials` · `11-directeurs-modal` · `12-recrutement` · `13-render-events` (`render()` + `bind()` + dispatchers) · `15-integrations` · `16-imports` · `17-fun` · `18-assistant` (AI assistant panel) · `19-home` (Accueil: `tHome()`, tab `home`, opened by clicking the « Konsilys » logo top-left — welcome, key figures of the visible scope, upcoming absences, pending approvals, role-filtered shortcuts; for a `trialing` admin a « Votre essai gratuit » card: days left, progress + per-step actions, `billing-open` button) · `14-data-boot` (`loadSB()`, `initApp()`, imports, approvals — ends with the `initApp()` bootstrap call).
- Global mutable state object **`S`** (in `js/01-core.js`). A single **`render()`** (`js/13-render-events.js`) rebuilds the view from `S`; call `render()` after mutating state.
- **Event delegation via `data-act` attributes** — buttons carry `data-act="..."` / `data-id="..."`, and one central click dispatcher (a long `if/else if` chain in `js/13-render-events.js`) routes them. To add a UI action, add the button with `data-act` AND a branch in that dispatcher.
- **`sb`** = Supabase client; **`SB_CID`** = the logged-in user's `company_id` (set after auth). **`loadSB()`** loads company data after login.
- Data reads go straight through the Supabase REST client (protected by RLS). Sensitive writes go to Edge Functions, never from the client.
- **Assistant** (`js/18-assistant.js`, floating « ✨ Assistant » button, also in demo): **100 % local rule-based parser, no external AI, no network call** — consultant/client/personal data never leave Konsilys (deliberate RGPD choice: do not reintroduce a third-party LLM without the owner's approval). `aiParse()` extracts intent (mission / absence + leave type), consultants (full name / last / first name, 1-typo tolerant, homonyms → choice buttons), client (known clients first, else « chez X »), French dates (« du 3 au 28 novembre », 03/11, « lundi prochain », « fin décembre », « pour 3 mois », start/end classified by the preceding word) and amounts (TJM, « forfait de 40 k€ », « 25 % de marge »). `aiRespond()` keeps a draft (`S.ai.draft`), asks for missing fields, and applies corrections (« plutôt à 700 € ») to the last pending card. Proposed actions are confirmation cards; « Créer » applies through the same rules as the forms (role rights, N+1 `submitApproval`, `checkLeaveBalance`, `tsRangeLocked`, `sbUpsertMiss`/`sbUpsertLeave` under RLS). The panel lives outside `#mc` and uses `data-ai` attributes (not the global `data-act` dispatcher); `aiMount()` is called at the end of `render()`. Actions: `create_mission`, `create_leave`, `create_consultant`, plus **edit/delete** — `update_|delete_` + `consultant|mission|leave` (`aiOp` detects supprime/modifie/prolonge/décale/transforme/change…, never when a create verb is present; target found by consultant + client / leave type + dates, several candidates → `pick-item` buttons; in an UPDATE the sentence's dates/amounts are the NEW values, except a leave type change « … en RTT » where dates identify the leave; cards show before → after; apply mirrors the `dc`/`dm`/`dl`/`sm`/`sl` handlers: `canEditTeam`, Time Sheet locks, `submitApproval` for `utilisateur`, `checkLeaveBalance`) (« Ajoute le consultant Julie Martin, Data Engineer, SCR 450 € » — `canEditTeam()` roles, duplicate names refused). **Free-trial onboarding:** for an admin whose subscription is `trialing`, the panel opens once automatically (`localStorage` key `ks-ai-trial-<company>`) with a start guide (days left, checklist consultants → mission → absence, quick buttons incl. Excel import via `openImportCons()`). To add an action: intent keywords in `aiIntent`, fields in `aiEvaluate`, a card in `aiCard`, an `aiApply…` function.
- **No web install:** the app is not installable from the browser (no manifest link, no install button, `beforeinstallprompt` blocked); the service worker remains for offline caching. **`sw.js`: app code (same-origin `.js/.css/.html`) is network-first** so a deploy is picked up on the first load (cache only as offline fallback); images/fonts/CDN cache-first. Add new `js/*.js` modules to its `SHELL` list and bump `CACHE` when changing the worker.

**Marketing site** (`index.html`, `fonctionnalites.html`, `solutions.html`, `tarifs.html`, `essai-gratuit.html`, `demo.html`) — static pages sharing `assets/site.css` (design tokens, components, CSS-only product mockups) and `assets/site.js` (sticky header, mega-menus, mobile burger, `[data-tabs]` tabs, `form[data-capture]` email → `/essai-gratuit?email=`, `.rv` reveal). Header/nav/footer markup is **duplicated in each page** (no build step): edit all six when changing them. Asset paths are relative (`assets/…`, `vendor/…`) so pages also work in `file://`. Old `/#abonnement` links are redirected to `/tarifs#configurateur`.
- `assets/signup.js` = the shared signup tunnel (`PLANS`/`MODULES` price IDs, `ksStartTrial()`): Supabase `signUp` (inactive company) → `seats-checkout` with `trial:true` → Stripe Checkout → `/login?checkout=success&trial=1`. Used by `/essai-gratuit` and the `/tarifs` configurator.

`esn_login.html` handles login and password-set for provisioned accounts (it captures the auth link type — invite vs recovery — before cleaning the URL).

## Core business invariants (do not break these)

- **Account creation happens ONLY through Stripe Checkout** (paid, or the 14-day free trial). A company is usable only when `companies.active = true`.
- **Free trial (14 days, no card):** `seats-checkout` with `trial:true` adds `trial_period_days=14`, `payment_method_collection=if_required` and `trial_settings.end_behavior.missing_payment_method=cancel` — only for a first signup of a company with no prior subscription and no `canceled_at`, max 25 seats. The webhook activates the company as for a payment (subscription status `trialing`). No payment method at trial end → Stripe cancels → webhook deactivates (same as cancellation). Admins see a countdown banner in the app (`render()`) with a button to the billing portal to add a payment method; the paywall offers re-subscription (same lines as the last subscription, no new trial). The app gates unusable companies behind `showPaywall()` (see `loadSB`, the `companies.select('active,...')` check). Never grant access without a paid subscription.
- **Roles** (6): `super_admin`, `admin`, `gestionnaire`, `sales` (labelled "Business Manager"), `recruteur`, `utilisateur`. `handle_new_user` reads `role` from signup metadata.
- **Multi-tenant isolation** is enforced by RLS using the `my_company_id()` SQL helper. Any new table with company data needs RLS scoped to `company_id = my_company_id()` — never `USING (true)`.
- **Cancellation:** the webhook sets `active=false` + `canceled_at=now()` (access blocked, data kept 1 year). `claim_subscription()` only *activates* — it never deactivates and never activates without a paid subscription row (inserted only by the webhook).
- **Provisioning:** on payment, `stripe-webhook` creates member accounts (`inviteUserByEmail`), a `consultants` fiche, and sets the buyer as N+1 (`pending_seats.invited_by_id`). Failed seats go to status `error` and can be re-run via the `retry-seats` function (admin button in Gestion des accès).

## Edge Functions & deployment

Functions in `supabase/functions/`:
- `stripe-webhook` — activates companies, records subscriptions, provisions seats, cuts access on cancel. **⚠️ MUST be deployed with `verify_jwt=false`** (Stripe sends no JWT; it verifies the Stripe signature instead). Deploying with the default `verify_jwt=true` silently breaks all payments.
- `seats-checkout` — builds the Stripe Checkout session; validates prices against an allowlist; first signup requires an owner licence (Admin **or** Super Admin, `OWNER_PRICES`); `trial:true` → 14-day free trial (see invariants).
- `billing-portal` — opens the Stripe Customer Portal (auto-creates the portal config if missing).
- `retry-seats` — re-runs provisioning for pending/errored seats (admin only).
- `create-checkout` — legacy, superseded by `seats-checkout`.
- `bd-unsubscribe` — public one-click unsubscribe link for Konsilys's own sales prospecting emails (`?t=<bd_prospects.unsub_token>` → status `desinscrit` + `bd_suppression`). **Deploy with `verify_jwt=false`** (clicked from emails). Tables `bd_prospects`/`bd_emails`/`bd_suppression` (+ `bd_sourcing_vus`/`bd_sourcing_curseur`, the sourcing memory: examined SIRENs and page reached per NAF code) are global (not tenant) with RLS on and no client grants; used by the `business-developer` agent (`.claude/agents/`).
- `assistant` — **disabled** (stub returning 410; delete it from the Supabase dashboard). The assistant runs locally in the browser.
- `extract-cv` — reads a candidate's PDF CV (from `candidate-files` storage) and asks the Anthropic API to extract structured work experiences (forced tool-use schema), returned to the app to pre-fill the candidate's "Expériences" (for the CV Entreprise). **Requires the `ANTHROPIC_API_KEY` secret** (optional `CV_MODEL`). ⚠ Sends CV content to Anthropic (outside the EU) — RGPD arbitrage needed before enabling. `verify_jwt=true`.

**Deploys go through the Supabase MCP tools**, not a CLI: `deploy_edge_function` for functions (pass `verify_jwt` explicitly), `apply_migration` for DDL, `execute_sql` for data. The `supabase/migrations/*.sql` files are a record of migrations already applied to prod via MCP — there is no local Supabase/migration runner here.

Stripe price IDs are hardcoded and must stay consistent across three places: `assets/signup.js` (`PLANS`/`MODULES`), `seats-checkout` (`ALLOWED`/`OWNER_PRICES`), and `stripe-webhook` (`PRICE_MAP`). Each role has a monthly and an annual price (annual = 10× monthly, i.e. 2 months free).

## Git & deploy flow

- Production deploys from the **`main`** branch (Vercel). Work happens on a feature branch; **changes are NOT live on konsilys.fr until merged to `main`** (Edge Functions & DB migrations, however, are deployed directly to prod via MCP and take effect immediately, independent of git).
- The GitHub squash-merge commit will show as "Unverified" — this is expected and not something to fix.
- **Owner preference: merge without asking.** Once a PR's CI (`checks`) is green and there is no conflict, squash-merge it to `main` directly — do not ask the owner for permission to merge (explicit instruction from the owner).
